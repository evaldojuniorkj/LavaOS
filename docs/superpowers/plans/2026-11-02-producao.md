# Fase 8 — Produção: Implementation Plan

> **For agentic workers:** execute task by task (one subagent per task, review after each). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LavaOS pronto para subir numa VPS com um comando: imagem Docker do app, Postgres com as duas roles, Caddy com HTTPS automático, backup diário com restore testado e um guia de deploy e atualização. O deploy real na VPS do usuário e a semana em paralelo com a planilha são feitos com ele (Tasks 6 e 7).

**Architecture:** `Dockerfile` multi-stage (build `standalone` + `public/` + `.next/static` + `drizzle/` + `scripts/migrate.ts`); `deploy/compose.yaml` com os serviços `postgres`, `migrate` (roda uma vez e sai), `app` (só na rede interna), `caddy` (80/443, `X-Real-IP` do socket, token mascarado no log) e `backup` (pg_dump diário com retenção); `.env` de produção fora do git a partir de `deploy/.env.example`.

**Tech Stack:** o atual + imagens oficiais `node:24-alpine`, `postgres:16`, `caddy:2`. Nenhuma dependência npm nova (as migrations usam `drizzle-orm/node-postgres/migrator`, já instalado).

**Estado:** não iniciado. Branch `fase-8-producao`, a partir da `main` (Fases 0–5).

**Spec:** §2 Ambientes, §9. [Roteiro](2026-10-31-roteiro.md), Fase 8. README, "Notas de produção". [Revisão da Fase 1](../reviews/2026-10-30-operacao-final-review.md), itens FASE-8.

## Global Constraints

- Nenhum segredo no repositório: `deploy/.env.example` só com placeholders; senhas e `BETTER_AUTH_SECRET` gerados na VPS (`openssl rand`). O compose recusa subir sem eles (`${VAR:?mensagem}`).
- O app **nunca** fica exposto: só o Caddy publica 80/443; app e Postgres ficam na rede interna do compose.
- Caddy sobrescreve `X-Real-IP` com o IP do socket (`header_up X-Real-IP {remote_host}`); o app já só lê esse cabeçalho.
- O log de acesso do Caddy não grava o token de `/acompanhar/<token>` nem de `/api/acompanhar/<token>/eventos`.
- Roles: `lavaos_owner` (dono, DDL, só migrations e backup) e `lavaos_app` (runtime, DML), com os mesmos grants de `scripts/db-local-init.sql`; o app conecta com `lavaos_app`.
- `LAVAOS_MODE=production`; `BETTER_AUTH_URL` = `https://<domínio>`; `LAVAOS_SETUP_TOKEN` só durante a instalação.
- Backup que nunca foi restaurado não conta: o restore é testado por script.
- Tudo verificável localmente com `tls internal` do Caddy (sem domínio) e na CI (build da imagem).

## Review Focus

- `curl` direto na porta do app ou do Postgres a partir do host: recusado (Task 2).
- Requisição com `X-Real-IP: 1.2.3.4` forjado pelo cliente: o app vê o IP real (Task 2).
- Abrir `/acompanhar/<token>` e conferir que o log do Caddy não tem o token (Task 2).
- Ícones, manifest e `_next/static` respondem 200 pela imagem (Task 1).
- Banco novo: `migrate` cria tudo, o app sobe com `lavaos_app` e o primeiro acesso funciona (Task 3).
- Backup de hoje restaurado num banco vazio tem as mesmas contagens de OS, pagamentos e comissões (Task 4).

### Task 2: Compose de produção com Caddy

**Files:** `deploy/compose.yaml`, `deploy/Caddyfile`, `deploy/.env.example`, `deploy/postgres-init.sh`, `scripts/smoke-producao.sh`.

- [ ] `postgres-init.sh` cria as roles e grants com senhas vindas do ambiente (equivalente ao `db-local-init.sql`, sem senha fixa).
- [ ] Compose: `postgres` (volume, healthcheck, sem `ports`), `migrate` (imagem do app, `node scripts/migrate.ts`, `restart: "no"`), `app` (`depends_on` migrate concluído, sem `ports`), `caddy` (80/443, volumes de dados/config), redes internas.
- [ ] `Caddyfile`: `{$LAVAOS_DOMINIO}` com `reverse_proxy app:3000 { header_up X-Real-IP {remote_host}; flush_interval -1 }` (SSE), log JSON com o token mascarado (filtro de `request>uri` por regex), cabeçalhos de segurança básicos (HSTS, `X-Content-Type-Options`).
- [ ] `scripts/smoke-producao.sh`: sobe o compose com `LAVAOS_DOMINIO=localhost` (Caddy `tls internal`) e confere: `/login` 200 via https; app e Postgres sem porta no host; `X-Real-IP` forjado ignorado (o rate limit do link público conta pelo IP real — 31 requisições seguidas com IPs forjados diferentes recebem 429); log do Caddy sem o token; SSE `/api/eventos` sem buffer (recebe `ready`). Derruba tudo ao fim.
- [ ] Verificar: o smoke passa localmente. Commit `feat(producao): compose com Caddy, HTTPS e rede interna`.

### Task 3: Backup e restore

**Files:** `deploy/compose.yaml` (serviço `backup`), `deploy/backup.sh`, `deploy/restaurar.sh`, `scripts/smoke-producao.sh` (estender).

- [ ] Serviço `backup`: `pg_dump -Fc` diário do banco com `lavaos_owner`, arquivo com data em `/backups` (volume ou pasta do host), apaga os mais antigos que `BACKUP_DIAS` (padrão 14). Roda um backup ao subir.
- [ ] `restaurar.sh <arquivo>`: restaura num banco novo (`pg_restore --no-owner --role=lavaos_owner`), confere as contagens das tabelas principais contra o banco de origem quando ele existe, e só troca o banco do app com confirmação explícita (`--trocar`).
- [ ] Smoke: com dados semeados (primeiro acesso + uma OS paga + uma comissão), backup → restaurar em banco de verificação → contagens iguais.
- [ ] Commit `feat(producao): backup diário e restore testado`.
